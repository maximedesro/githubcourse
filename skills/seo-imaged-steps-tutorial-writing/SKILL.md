# Write illustrated SEO tutorials

## Plan around the reader's task

- Identify the search phrase, intended reader, platform, and result. Keep the article centered on the task in the title. Put the requested primary workflow first. When asked to add a second workflow to an existing article, retain useful text, images, code, and links and group each workflow under its own heading.
- Use the requested title and target post. Read current content and check publication status before editing. Save a new article as a draft unless publication is requested. When authorized to edit an already published article, update that post. Use the browser editor when requested.
- Read a few relevant articles by the publisher to match their voice. For ShapeDividers, use direct instructions, short numbered steps, exact interface labels, and practical first-person examples such as “I used 120 px.” Write for a beginner who needs to know what to click, what to paste, and what result to expect.
- Use the exact focus keyword near the start and in several relevant headings where it reads naturally. Open with what the feature does and the result the reader will build. Carry one concrete example through the generator, export, setup, and finished result. Keep secondary export formats and platforms brief unless the user asks for a full walkthrough.

## Test the procedure before writing

Use the current product and actual exported code. Match the instructions, screenshots, class names, filenames, settings, and visible result. If the live generator fails, diagnose it first. If an authorized local copy is needed, use the same generator and catalog where possible and disclose the substitution.

For ShapeDividers.com:

- Open the shape library from the preview, choose a shape, and explain the relevant controls. Use **Top** or **Bottom** between stacked sections. For a photo beside a solid panel, apply the divider to the photo column's edge that touches the panel. Match the divider fill to the neighboring background and remove the gap. For a gradient, match the neighboring panel to the stop at the actual joining edge and inspect the rendered seam.
- Explain the axes by direction. Long Axis follows the edge, so on a vertical divider it controls height and Short Axis controls how far the shape reaches into the column. For a horizontal divider, Long Axis controls width and Short Axis controls height. Explain Position, Flip, Gradient, Animate, and Responsive when relevant. Responsive can use different settings for desktop, tablet, and mobile. If side-by-side columns stack, test hiding the side divider or switching to a horizontal divider at that breakpoint.
- Use **Copy Code → Copy CSS code → Copy**. Check whether the selected effects support CSS export. Some settings require Premium or another format. Preserve the full export and identify the actual class in its first selector. The class can vary across exports. In a stylesheet, keep the selector's dot. In the HTML class attribute or a builder's class field, omit the dot and separate classes with spaces.
- For plain HTML, show the target element and where the styles go. Include either a linked stylesheet example in the head or style tags in the head, as appropriate. Show enough layout CSS to reproduce the result, including a visible section height or padding, the adjoining backgrounds, and the target class. The CSS export embeds the artwork and usually draws it in a pseudo-element. Test the loaded stylesheet, matching selector, visible divider, and adjoining edges. Reserve room where the artwork would overlap text.
- For Gutenberg, build the example with native Group and Columns blocks. A horizontal divider can join stacked Groups. A vertical divider can join two columns with the shape applied to the photo Group. Give the Group a background and enough height. For CSS, insert a Custom HTML block above the layout and paste the complete export between style tags in its HTML field. A stylesheet or site-wide CSS field takes the rules without style tags. In List View, select the target Group and enter the generated class under **Block → Advanced → Additional CSS class(es)**. For inline SVG, insert a Custom HTML block **inside** the target Group and keep the export's positioning styles, wrapper, and SVG together. Set the host to relative positioning and clip overflow as needed. Check for inherited block spacing on the absolute SVG wrapper. A scoped margin reset on that wrapper fixed a vertical offset in the tested Gutenberg layout. Use the front end to verify both methods because the editor preview can differ. If WordPress strips markup on save, check permissions and the [Custom HTML block documentation](https://wordpress.org/documentation/article/custom-html/).
- When relevant, give readers a brief choice of other formats. The inline SVG export provides markup with positioning styles. An SVG mask export can use an external SVG for the shape while CSS controls its fill or gradient. Link to the [inline SVG guide](https://shapedividers.com/how-to-use-the-svg-code-from-shapedividers-com/) and the [SVG mask export guide](https://shapedividers.com/how-to-use-the-svg-mask-export/).
- Link to the current [platform documentation](https://shapedividers.com/documentation/) and relevant individual guides. Verify current URLs against the documentation index before using them. Use a concrete link label such as **See all documented platforms**.

## Capture the steps readers need to see

- Make each screenshot answer a question that the text creates. Useful moments include the shape picker and selected thumbnail, direction and axis controls, the selected export tab and Copy button, the class in the export and destination, and the finished front-end layout. Place the image directly below the corresponding action. Split multi-action instructions when an image would otherwise have an ambiguous placement.
- Use the actual logged-in or public interface as appropriate. Crop to the controls and retain enough context to locate them. Remove admin chrome and account details from reader-facing images. Check that control labels, code, and selected states are readable at article width. Alt text describes what the screenshot shows. Captions tell the reader what to do or look for.
- Show the specific state promised in the text. If mentioning Responsive mode, put a small close-up beside that sentence with the toggle outlined. For a Custom HTML paste step, include **one image with the HTML tab, the generated CSS, and both opening and closing style tags visible together**. The block inserter and export dialog can illustrate their own steps. An editor screenshot may reflow the code to fit while preserving behavior. If using an excerpt, label it and tell the reader to keep the full export. For Gutenberg SVG, show the markup and wrapper as well as their location inside the Group.
- Upload the final images to the intended site's Media Library. Use descriptive filenames, the returned attachment URLs or IDs, and meaningful alt text. Confirm each image belongs to the intended step and displays at a readable size. Keep code examples as selectable text even when a screenshot also shows them. Escape HTML in code samples and check for clipping on narrow screens.

## Save and verify the actual deliverable

- When WordPress uses the Classic Editor, its Code tab is useful for placing structured HTML, code samples, and figures. Check the destination and status before saving. Confirm the update notice and reload the editor if persistence is uncertain. If a save from Code view fails to persist, switching to Visual and using the primary save control worked in this workflow. For drafts, open WordPress's latest Preview from the editor, since an older preview tab can show stale content. For published edits, check the actual public page.
- Verify the heading order, focus keyword placement, screenshots and alt text, code sample rendering, links, and the working demo. Scroll to lazy-loaded images before treating them as broken. Report the post's actual status, link to it, and include an example screenshot when appropriate.

## Optional live examples

If requested, build a demo on the specified test page or in CodePen. Preserve existing examples unless the user asks to replace them. Give separate CSS and inline SVG pens distinct titles and URLs. Use the actual generator exports. CSS artwork can be embedded in generated pseudo-elements. An inline SVG pen should contain real SVG elements and the corresponding generated positioning styles. Check the final geometry, use side-by-side photo and solid regions for left and right dividers where requested, and preserve any documented pause control or reduced-motion behavior. For a gallery with **edit this shape** links, carry through the corresponding shape ID and supported preset settings, verify a representative link loads the expected preview, and use the homepage arrow treatment when requested. Save and verify the public preview. Link the demo in the tutorial only when it helps readers follow the requested workflow.
